# 同类产品对标：他们为什么有吸引力，我们差在哪

日期：2026-09-25
对象：`starpivot`（C++17 物理内核 + `viewer/index.html`、`viewer/universe.html`）
方法：查 25 个同类产品的公开资料，按"能不能对上我们的功能面"的维度拆解，
再把差距逐条落到改动上，改完用 jsdom 以用户视角重走一遍。

---

## 一句话结论

**他们的共同点是：把「按下按钮 → 看见结果」的距离压到零，并且给你一个「想再来一次」的理由。**

我们之前两样都缺：改了参数要等重算、还常常没有任何反馈；而且整个产品没有任何目标。
内核比大多数竞品**更可验证**（他们有画面，我们有判据），但这一点在页面上一个字节都没露出来。

本轮把这两条补上了：**零距离反馈**（脏标记 + 一键标定 + 预设立即生效）与
**再来一次的理由**（稳定性挑战 + 分数 + 最佳成绩）。

## 二、把 25 个产品摊开之后，归纳出的 10 条吸引力机制

| # | 机制 | 代表 | 我们改之前 | 本轮 |
|---|---|---|---|---|
| M1 | **零成本即时试错** | WorldBox 的神力没有消耗/冷却/失败态；Solar Smash 点一下立刻炸 | 改了参数要等重算，而且**一半控件改了毫无反应** | ✅ 脏标记：按钮变「重新计算（参数已改）」+ 说明"画面还是旧结果" |
| M2 | **明确的目标 + 分数 + 结束条件** | Super Planet Crash 的 500 年 + 分数 + 排行榜 | 完全没有。它是模拟器，不是游戏 | ✅ 稳定性挑战：120 年、两条判据、按地球质量×存活年数计分、最佳成绩 |
| M3 | **一键开局 / 模板** | SPC 的模板下拉；Universe Sandbox 场景库；NASA Eyes 150+ 任务 | 一张空表 + 9 个裸数字框，得先懂开普勒根数 | ✅ 8 个预设，每个都真跑通（判据逐个验证） |
| M4 | **点击直接放置** | SPC：在恒星附近点一下就放星 | 只能填表 | ❌ 未做（见"还差什么"） |
| M5 | **时间控制** | KSP 两档时间加速；NASA Eyes 1950–2050；Celestia ±1000 年 | 只有播放/暂停 + 一根没刻度的滑杆 | ✅ 逐帧前后、回首尾、**点事件行或"达到某阶的时刻"直接跳过去**；❌ 反向时间、变速档位未做 |
| M6 | **分享与社区** | Universe Sandbox 创意工坊；SPC 分享 URL + 排行榜；Juno 上传站 | 只有本机 localStorage 存档 | ✅ 分享链接（编码进 URL hash，对方那台机器现场重算）；❌ 排行榜未做 |
| M7 | **画质/尺度工具** | NASA Eyes 的 Compare Size / Telescope Mode；Solar System Scope 真实比例开关 | **默认把圆画成多边形**（水星一圈只有 2 个采样点） | ✅ 内核回显"每圈采样点数"画质读数 + 一键标定 + 帧间插值；❌ 真实比例/大小对比未做 |
| M8 | **知识锚点 / 百科** | Solar System Scope 3D 百科；NASA Eyes 任务故事 | 有分层口径与常量回显，但没有"这颗星是什么" | ❌ 未做 |
| M9 | **失败即教学** | KSP 190 次失败；Children of a Dead Earth 的"忠实但劝退" | 内核会明确拒绝，但页面把拒绝信息擦掉了 | ✅ 告警条（上轮修）；❌ 没解释"为什么错"（`e≥1` 的物理含义没写） |
| M10 | **观感** | SpaceEngine / Solar System Scope 的纹理与光照 | 几何点线 | 不追。但**运动连续是底线**，本轮补上（采样 + 插值） |

### 我们真正比他们强的地方（也没藏）

1. **同一套内核里同时有**：恒星星历 → 真实 TLE → 碰撞预警 → N 体辛积分 → 位置驱动的演化阶梯。
   竞品通常只有其中一两块，而且是渲染优先、**物理精度不可验证**。
2. **分层诚实**：页面上写明哪层是真公式、哪层是编排，常量一律取内核回显（`freezing_K`、
   `points_per_orbit_ok`、`earth_mass_msun` …）。同类产品里几乎没人这么做。
3. **判据可查**：五层判据（静态 / 独立复算 / 真代码单测 / 端到端 / 页面级端到端），
   每个数字都能追到出处。这一条在"模拟器"这个品类里是稀缺的。

**问题是这三条一件都没出现在页面上。** 玩家看不到"可验证"，只看到"内行星在乱跳"。

## 三、以用户视角重走一遍

（这一遍是用 jsdom 真加载页面、真调内核走出来的；jsdom 不渲染像素，
所以"好不好看"这一项我给不出结论，只能给"动起来对不对"。）

**第一次打开。** 默认太阳系、50 年、2000 帧。3.1 秒后出第一帧。
右下角多了一行新东西：

> 画质：最内圈天体每圈 **9.6** 个采样点（够用线 24、理想 60 → 偏稀）·
> 最短环绕周期 0.241 年是内核按 vis-viva 从各天体 t=0 状态算出的，页面不参与。
> 〔改成 16 年 / 2000 帧〕

**——这是我第一次在这个页面上看到"它自己承认哪里不够好"。** 点那个按钮：
年数变成 16、帧数保持 2000，读数从 9.6 跳到 **30.1**，达到"够用"，建议按钮自己消失。
（改之前：50 年 / 400 帧 → 水星每圈 **2.0** 个点，也就是每帧跳到轨道对面。）

**想加一颗行星。** 一行 8 个按钮：「太阳系九星 / 8 字三体 / 类地行星 / 热木星 /
紧凑六行星 / 彗星掠日 / 双星系统 / 行星撞地球」。鼠标停上去会说明这是什么、用多少年多少帧。
点「行星撞地球」→ 场景切到自定义、两颗会撞的行星进表、**碰撞模式顺手切成"撞击碎裂"**
（否则默认"碰撞关"，一个叫"撞地球"的预设什么都不撞 —— 这是判据抓出来的，见下）。
3 年内 4 次事件，第一次在 t = 0.798 年。

**想调点东西。** 把「半径放大」从 450 拖到 3000。
按钮立刻变成 **「重新计算（参数已改）」** 并且下面冒出一行：
"上面有参数改过了，但还没重算 —— 画面现在显示的仍是改之前的结果。"
点一下，参数真的下发（判据验证过 payload 里的 `radius_scale=3000`），按钮复原、提示消失。

**——这条很重要。** 改之前，同一个动作什么都不会发生，玩家会以为"半径放大"坏了。

**想看那一刻。** 时间轴上多了 ⏮ ◀ ▶ ⏭。点一下 ◀ 会**先自动暂停**再退一帧
（否则播放循环立刻把位置拽走）。想直接跳到碰撞那一刻？在事件时间线里点那一行。
演化表里"达到该阶 (年)"那一格现在是带下划虚线的数字，点一下跳到 **t = 10.452 年**
（目标 10.4518，落在最近的帧上）。

**——原来数据一直在表里，只是点不过去。**

**想给别人看。** 点「🔗 复制分享链接」，地址栏变成 `#s=eyJzY2hlbWEi…`，
页面上也把链接明文列出来（浏览器不允许自动复制时能手动拿），并写明
"对方那边是**现场重算**，分享的只是选择，不是一段录像"。
对方打开：页面说"已按分享链接载入"，设定全部生效，
而且**只点逐帧浏览不会冲掉他自己那份会话**（这是判据抓出来的第二个真缺陷，见下）。

**想赢一次。** 点「开始挑战」→ 自动切到"自定义 + 只放太阳"、120 年、碰撞合并。
加两颗会撞的行星再算一次 → 得到：

> **失稳**：发生了合并吸积
> 存活 0.80 年 → **得分 1.6**（2.00 个地球质量 × 0.8 年）

（这个数是对的：判据抓到过一版把碎块和母体重复计入，会虚高到 3.00。）

**还差什么（用户视角的真实感受）：**

1. **仍然要打字。** 加行星还是填 9 个数字框。Super Planet Crash 是"在恒星附近点一下就放一颗"——
   这一条我们没做，而它恰恰是最能把路人变成玩家的那一下。
2. **画面上没有任何"这是什么"的信息。** 点到一颗星只知道它在哪个轨道平面，
   不知道它多大、多重、现在多少度。Solar System Scope 的 3D 百科和 NASA Eyes 的任务故事都在干这个。
3. **不能反向走时间。** Celestia 能前后走 1000 年，NASA Eyes 能回到 1950 年。
   我们只有单向的 0→终点。
4. **没有排行榜。** SPC 有个 High Scores 列表，这是"再来一次"最强的燃料。
5. ~~**首屏 3.1 秒**（2000 帧的 JSON 换来的画质）。~~ **这条是错的，已更正**：
   那是探针里的 `settle(2500)` 固定等待被我当成了加载时间。实测（`_probe_firstpaint.js`）：
   内核 2000 帧 265 ms（1.40 MB stdout）→ 经网关 348 ms（JSON.parse 16 ms）→
   **页面从加载到画面有内容 513 ms，首帧 render 54 ms**。首屏不需要优化，
   更不能拿一个自己造出来的数字去立项。
6. **失败的解释不够。** 内核说 `--body e must be in [0,1)`，玩家不知道 `e=1` 意味着抛物线、
   `e>1` 意味着双曲线 —— 即"这颗星根本不再绕着回来"。

## 四、本轮改动清单

**内核（`tools/starpivot_cli.cpp`，需重编译）**

| 改动 | 为什么 |
|---|---|
| `--years` / `--dt` / 数值参数统一走 `num_arg()` | 原来 `--years abc` 会抛未捕获的 `std::invalid_argument` → **进程 abort**（0xC0000409） |
| `years_given` / `dt_given` 与 `-1.0` 哨兵分开 | 原来 `--years -5` 被当成"没给"，**静默按 50 年跑** |
| `years>0`、`dt>0` 校验 | 原来 `--dt 0` 返回 `status:"ok"` + `frames:[]`，页面收到就崩 |
| 步数上限 5e7（约 40 秒） | 原来 `--years 1e6` 不拒绝，实测要算十几分钟，网关 180 秒超时 |
| 回显 `sampling` 块（最短环绕周期 / 每圈采样点 / 建议帧数 / 建议年数 / 够用线 / 标定方法） | 画质不能靠页面拍脑袋；周期用 vis-viva 从内核自己的 t=0 状态算 |
| 回显 `earth_mass_msun`，并让行星表的地球质量引用同一常量 | 原来会出现"回显 3.0034896149e-6、表里 3.003489e-6"这种同一件事写两遍 |

**页面（`viewer/universe.html`）**

| 改动 | 对标 |
|---|---|
| 默认帧数 400 → 2000；画质读数 + 一键改成推荐值 | M7 |
| 帧间线性插值（默认开，明确标注"只影响显示平滑度"） | M10 |
| 脏标记（8 个不自动重算的控件）+ 说明条 | M1 |
| 逐帧导航 + 点事件/阶跳到那一刻 | M5 |
| 分享链接（URL hash，对方现场重算，不冲掉对方存档） | M6 |
| 8 个预设场景（每个都真跑通） | M3 |
| 稳定性挑战（120 年 / 两条判据 / 计分 / 最佳成绩） | M2 |

**诚实性修补**：`viewer/index.html` 顶部写明"上半页这三份轨道是随页面打包的预计算样本，
加载时不会调用本地内核（实测只发过一次 `/api/health`）"。

## 五、这轮判据抓出来的两个真缺陷

写代码时自己没意识到的，全靠判据逼出来：

1. **预设「行星撞地球」根本不撞。** 默认碰撞模式是"关（质点互相穿过）"，
   一个叫"撞地球"的预设什么都不撞 —— 名字是空承诺。判据（"预设里的每一次事件数必须 > 0"）
   直接把它顶出来，于是预设现在自带 `collide: fragment`。
2. **仅浏览就认下了别人的会话。** 打开分享链接、只点一下 ▶ 逐帧，
   就把对方的宇宙写进了自己的 localStorage —— 因为 `seekFrame` 里调了会解除封锁的
   `saveState()`。拆成 `saveStatePassive`（只落盘）与 `saveState`（认下这份会话）之后才对。

另外判据自己也错了 5 处（数请求把 `/api/health` 算进去、没锁暂停态导致指纹一直在变、
把"请求已发出"当"响应已收到"、用告警色做启发式判断、以及把 `frames` 长度当成 `samples+1`
—— 实际是 `every = floor(total_steps/samples)` 向上取整，12000/900 会给出 925 帧不是 901）。
**判据通过只说明"没抓到问题"，不说明"没有问题"。**

## 六、还差什么（按性价比排序）

| 优先级 | 事项 | 为什么 |
|---|---|---|
| 1 | **点画面放行星**（M4） | Super Planet Crash 最核心的那一下。我们的自定义表已经能接受任意初值，缺的只是"把点击换算成 a/e/M0"——这是纯几何反解，属于显示层 |
| 2 | **选中天体后的信息卡**（M8） | 现在点一颗星只知道它的轨道平面。质量、半径、密度、当前距离、辐照度、地表温都是内核已经回显的 |

**这一轮自己当玩家玩出来的三个问题**（探针也顺手补上了判据）：

1. **挑战里用鼠标放的天体不计分** —— 挑战开始时把名单定死了，而"开着挑战点画面加行星"恰恰是最自然的操作路径。实测分数从 2.4 变 3.2、质量项 3.00 → 4.00 个地球质量之后才算对。
2. **距离标尺只画出 10/20/50 AU** —— 基数只在 10 的整数次幂上取，视野落在 3–30 AU 时最小一圈就是 10 AU，"想在 1 AU 附近放一颗"等于没有刻度。补上 10 的下一档（现在最内圈是 1 AU）。
3. **PNG 导出"没验过就宣称成功"** —— 某些宿主 `toDataURL` 不抛异常但返回空数据，页面照样报"已导出"。改成先验格式与长度，拿不到就如实报失败。

另外修了一个**潜在缺陷**（没能在当前路径上复现，属防御性）：信息卡的刷新键只算了 (选中编号, 帧号)，漏了"数据版本"，同一颗星停在同一帧而数据换过时会命中缓存、留着上一版数值。已把 `dataStamp` 并入键。

**还有一条不是产品缺陷、而是检查器缺陷**：`_check_bio_page.js` 的"剥掉字符串后页面里不该有物理常量"这条判据，其剥串器不认识**正则字面量** —— 页面里只要有一个 `/[",]/`（`sanitizeBody` 里就有），里面的引号会被当成字符串开头，从此后面所有字符串与代码的配对**全部错一格**，于是"页面自己算 273/373"这种假失败就出现了。上一轮没暴露纯属运气。现在剥串器认识正则了，并加了一条自检：剥完之后不该剩任何引号（哨兵改成不带引号的 `\u0001`），**让剥串器自己被判据盯着**。
