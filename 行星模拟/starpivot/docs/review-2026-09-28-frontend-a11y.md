# 前端审查：语义与无障碍（2026-09-28）

审查对象：`starpivot/viewer/` 的四页（`home.html` / `index.html` / `universe.html` / `kids.html`）
与两个脚本（`world.js` / `demo.js`）。

**为什么单独做这一次**：现有判据（`_check_bio_page.js` 63 条等）管的是"页面有没有算物理、字段名对不对、
控件有没有死元素、颜色对比度达不达标"，**完全没有覆盖语义与无障碍**。这一节专门补那块空白。

## 0. 方法与它的局限（先说清楚）

- **真 Chrome 采集**（Playwright + 本机 Chrome，`_audit_frontend.js` / `_audit_frontend2.js`），
  不是读源码猜；四页都真加载、等首屏画完再读 DOM。
- ⚠ **两条 a11y 专用通路都没走通，如实记下**：
  - `page.accessibility.snapshot()` 在所用 Playwright 版本上**已弃用**，抛异常；
    异常被 catch 吞掉后，第一版脚本报出 `buttonTotal=0` 却 `unnamedCount=1` —— **两个数自相矛盾**，
    是脚本的 bug，不是页面的结论。
  - 改试 `locator('body').ariaSnapshot()` 后，按钮行数统计仍为 0，与 DOM 事实不符 → **判为不可用，不采纳**。
- 因此下面的结论**全部来自直接读 DOM**（`page.evaluate`）。
  它给出的是"可访问名的近似值"（`aria-label` 或可见文字），**不等于**浏览器完整可访问名算法；
  对本项目这种"按钮都带文字"的页面足够，但要知道这个边界。

## 2. 对照规范：确认的问题

### 2.1 `aria-live` 全为 0 —— 动态结果不会被告知（WCAG 4.1.3 Status Messages）

四页有大量"算完了才知道"的动态文本：状态行、画质读数、告警条、选中天体的数据卡、
挑战成绩、分享链接提示。它们**都是直接改 `textContent`/`innerHTML`**，没有任何 `aria-live` 区域，
屏幕阅读器用户**不会被告知页面更新了**。这是本次最值得修的一项。

### 2.2 `<label>` 全都没有 `for` —— 视觉上有标签，语义上没有（WCAG 1.3.1 / 3.3.2 / 4.1.2）

全站 **36 个 `<label>`，带 `for=` 的 0 个**（index 8 / universe 26 / kids 2），
写法一律是相邻但不关联：

```html
<label>场景</label>
<select id="scenario"></select>
```

实测后果：`index` 的 **8/8**、`universe` 的 **43/48** 表单控件 `el.labels.length === 0`
（即"这个控件没有标签"）。**视觉上每个控件旁边确实写着字**，所以这是纯粹的"语义缺失"，
不是排版问题 —— 鼠标用户毫无感觉，读屏用户会听到一串无名控件。
`universe` 里连时间轴（`#scrub`）、播放速度（`#speed`）这类高频操作控件也在其中。

### 2.3 `<canvas>` 没有替代文本（WCAG 1.1.1 Non-text Content）

`index` 与 `universe` 的主画布既无 `aria-label`、也无 `role`，canvas 内 fallback 文本长度为 0。
画布是这个站的主要内容，读屏用户完全没有入口。

### 2.4 标题层级跳级（WCAG 1.3.1）

`home` 是 `h1 → h3`，`universe` 是 `h2 → h4` —— 中间缺一级，按标题导航的用户会以为漏了内容。

### 2.5 `aria-label` / `role` 全站为 0

纯语义 HTML，没有一处增强标注。这本身不算错（原生标签够用时不写 ARIA 是**正确**做法），
但它同时也意味着上面那些缺口没有任何补偿。

## 3. 已经做对的地方（如实说，不是凑数）

- **外部请求：四页全 0** —— 真的零外部依赖，离线可用（`world.js` 打包进仓库就是为了这个）。
- **console 错误与警告：四页全 0** —— 没有隐性报错被忽略。
- **`prefers-reduced-motion`：四页都处理了** —— 减弱动效做在前面了，这在同类项目里是少数。
- **`lang="zh-CN"`：四页都有**。
- **`onclick=` 0 处、`var` 0 处** —— 事件全部 `addEventListener`，声明全部 `const/let`。
- **`<button>` 全部带可见文字**（可访问名没有缺失）—— `index` 3/3、`universe` 86/86 都有名字。
- 颜色对比度已有判据盯着（三主题 × 三档文字 × 三底色 ≥ 4.5:1），不重复审。

## 4. 引入前端库的代价评估（这是你问的"对照前端库"）

现状是**刻意零依赖**（内核零第三方数值依赖、前端零外部请求，两个层面同一种性格）。
所以要引入库，先看代价：

| 想要的效果 | 候选库 | 能带来什么 | 代价 |
| --- | --- | --- | --- |
| H-R 图 / 能量曲线更漂亮 | **ECharts**（可打包进仓库） | 坐标系、缩放、提示框、导出图片 | 发布包 +约 1 MB；图表逻辑要重写一遍；**不破坏离线**（打包即可） |
| 星下点地图更好看 | Leaflet / MapLibre | 真实底图、缩放平移 | ⚠ **底图瓦片必须联网** → **直接毁掉"离线可用"这条特性**；不推荐 |
| 三维宇宙 | Three.js | 真 3D 视角 | 项目现在是 2D canvas，等于重做渲染层；+600 KB |
| 界面组件统一 | Tailwind / Bootstrap | 统一样式 | 与现有 48 个同名设计令牌**打架**，四页令牌体系要推倒 |

**当前判据里没有任何一条盯着"零外部依赖"**，所以引入库不会让判据变红 —— 但"离线可用"是本项目的
既有设计意图（世界地图数据就是为此打包的），引入 CDN 库会实质违反它；打包进仓库则不违反，代价是体积。

## 5. 建议（按性价比排序，前两项不动架构）

1. **给动态文本加 `aria-live`**（改十几处 `textContent` 赋值点）：收益最大、不碰渲染、不影响体积。
2. **给 36 个 `<label>` 补 `for="<控件id>"`**：一处一行，纯属性补全，不改结构、不改样式、不影响判据。
3. 给两块主画布加 `aria-label` 与简短 fallback 文本。
4. 修两处标题跳级（`h3`→`h2`、`h4`→`h3`）。
5. 引入 **ECharts** 只换图表（H-R 图 + 能量曲线），**打包进仓库保离线** —— 这是唯一我认为值当的引库方案。
6. **不建议** Leaflet 类底图库（联网瓦片与离线特性冲突），也不建议换 UI 框架（会与既有令牌体系打架）。

以上 1–4 属于"补齐语义"，**不改任何视觉**，可以只做它们；5 是真正的"引入前端库改画面"，
要你点头再动（会 +1 MB 发布包，并需要重跑全量判据与重新发布）。

### 三处刻意偏离原建议，理由写在下面

**① 建议 3 说要加 canvas fallback 文本，我没加。** `<canvas>` 里的子元素就是它的 fallback，
但那等于往 HTML 里塞汉字 —— 而 `_check_kids.js` 是拿"去掉 `<details>` 的**整份 HTML 文本**"
（属性文本也在扫描范围内）去比对 40 词术语黑名单的，`_check_home.js` 另有首屏 420 汉字上限。
往画布里塞字会直接踩这两条判据。所以只加**属性**：`aria-label` 是属性不是文本节点，
进不了 `textContent`，也给读屏提供了名字。代价是"画布画了什么"仍只有一句话概括，
这个局限保留。

**② 建议 4 说 `h3`→`h2`、`h4`→`h3`，我没换标签，改用 `aria-level`。** `home.html` 里
`h2` 是 16.5px、`h3` 是 15px —— 换标签会**真的改字号**，与"不改视觉"冲突。
`<h3 aria-level="2">` 在保留原字号的同时修正了大纲层级，axe 这类工具也认 `aria-level`。

**③ 建议 2 说"36 个"，实际补了 30 个。** 差的 6 个各有原因，不是漏了：
- 5 个是**嵌套式** `<label><input>…</label>` —— 隐式关联已经生效，再写 `for` 是冗余；
- 1 个是 `universe` 的「逐帧」，它后面跟的是四个 `<button>`，而 **`<button>` 不属于
  labelable 元素，`for` 指不过去**。改成 `<span class="grouplabel">`，并在 CSS 里给这个类
  原样搬了 `label` 的那条声明（字号/颜色/`display`/下边距逐字相同），视觉不变。

### 反过来：一处**故意不加**

`#statline`（状态行）与 `#tlabel`（时间读数）**每帧都在变**。给它们挂 `aria-live`
会让读屏在播放时**一直念**，比不念更难用。同理 `#play`、`#dirbtn` 这类按钮文案也不加 ——
按钮自身状态由辅助技术按控件读。live region 只留给"算完了说一次"的那类。

### 验证

- **静态自查 74 条 fail=0**（`_a11y_verify.js`）：逐条确认 `label[for]` 指向的 id
  **真的存在**、且指向的是可关联控件（`for` 指错地方不会报任何错，是最容易静默漏掉的一类），
  并反向确认每个控件都有 label 指着它；同时检查标题不跳级、高频区没挂 live。
- **动态自查 28 条 fail=0**（`_a11y_verify_dyn.js`）：那两处 JS 运行时才生成的滑块，
  让页面真跑起来（jsdom 执行内联脚本 → 切简单模式 → 加行星）后确认
  `for` 与 `id` 对得上、且多颗行星时 id 不撞车（实测 `ba0/be0…ba3/be3`）。
- 四页内联脚本过 `node --check`（0 段语法错误）—— 我改了 JS 里的字符串拼接，
  引号错一处整页就崩，所以这一项单独验。
- 静态判据 `_check_home / _check_kids / _check_bio_page / _check_orbit / _check_session`
  与 `_cmp_lists.py` 全 rc=0、落盘文件 mtime 在本轮。

### 没验过的（如实记）

- **没有用真读屏软件（NVDA/VoiceOver）听过**。`aria-live` 的实际朗读时机与打断行为
  只有真读屏能验，这里只保证"该有的属性在、该安静的地方没加"。
- **`aria-label` 的措辞是否贴切**未经人工复核。
