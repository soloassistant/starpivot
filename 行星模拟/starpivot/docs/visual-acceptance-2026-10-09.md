## 四、缺陷清单（按严重度）

### ① 【中】`/universe` 移动端：高级选项里的控件被**永久裁掉**
- `details#advbox` 带 `overflow-x: hidden`，把子元素裁掉且**自身不横滚**（`scrollWidth == clientWidth`）。
- 后果：`select#collide`（**碰撞模式**）宽 **487 px**，在 390 px 视口里**右侧 130 px 永远够不到**；
  同一祖先下另有 `select#scenario` + 一个 `div` + 一个 `label` 各被裁 **26 px**。
- 因为页面整体 `overflowX = 0`、父级 `overflow-x:hidden` 且不可滚，**用户没有任何办法看到被裁的部分** ——
  这比"能横滑"严重。
- 证据：`_va/_report_mobile_deep.json`（`/universe` 的 `clipped` 段）。

### ② 【中】`/universe`：「天体类型」链接对比度 1.72，几乎不可见
- 原因：样式表里只有 `a{display:inline-flex;align-items:center;min-height:44px}`（只设布局，**没设 `color`**），
  于是链接继承**浏览器默认链接色 `#0000EE`**，叠在深色底上。
- 位置：`viewer/universe.html:387`（"怎么开始…想自己放就点**天体类型**再双击画面"）。
- 证据：`_va/crop_universe_badlink.png`（放大后肉眼可见：周围文字是浅色，唯独这个链接是暗蓝）。

### ③ 【低】`/orbit` 移动端：整页可横向拖动 11 px
- `select#scenario` 宽 368 px、左偏 33 px → 右边界 401 > 390；**它没有裁切祖先**，
  于是把整个文档撑到 401 px。
- 证据：`_va/_report_mobile_deep.json`（`/orbit` 的 `clipped` 段，`祖先 (无裁切祖先)`）。

### ④ 【低】`/universe`：「无光照」图例文字对比度 3.58
- `#6b7280` 灰叠深色底，12.5 px。位于**折叠的**「其余 31 种」里，不点开看不到。
- 证据：`_va/crop_universe_palette.png`（展开后的 8 个常用类型是正常的）。

### ⑤ 【极低 / 文案】首页内核状态写「平台 **nt**」
- 直接把 Windows 的 `nt` 抛给用户看（`home.html` 渲染的 `平台 nt`）。
- 不是功能问题，是"把内部值直接透出"。

## 五、我差点误报的两处（方法记录）

1. **`/orbit` 地面轨迹"没有底图"** —— 全页缩略图里那片浅色上只有蓝线，
   看着像没画陆地。**放大到 3 倍后确认底图在**（浅灰 `#9aa3b2`，Natural Earth 110m，
   图例里也写着）。**结论：全页长图不能用于判断"有没有画"，必须定点放大。**
2. **移动端 `/` 报 102 处越界** —— 深查后全部落在 `overflow-x:auto` 容器内，**可横滑**，
   不是缺陷。**结论：`bad-elems > 0` 本身不是判据，必须再问一句"祖先裁不裁"。**

## 六、本轮**没有**验到的（诚实标注）

- **没有真机验收**：只用了 Chrome 的设备仿真视口（390×844），**没上过 iOS/Android 真机**。
- **没有验交互动效的视觉**：只截稳定帧，没看 hover / focus / 按下态 / 动画中间帧。
- **没有验 200% 缩放、打印样式**下的表现。
- **没有验系统深浅色主题**：四页都不含 `prefers-color-scheme`，也没有主题开关
  （所以"三主题 × 三文字 × 三底色"那套只存在于令牌层，本轮**未在渲染层复验**）。
- **`#eventcard`（碰撞/碎裂/重聚事件时间线）本轮没有覆盖**：它 `display:none`，
  只有出现事件时才显示；我没有构造会碰撞的场景，所以**这一块的外观完全未看**。
- **焦点可达性只验了"有没有布局盒"**，没验屏幕阅读器顺序（那属于 a11y 探针的职责）。
- 本轮**只验了 localhost**，**未验线上**（线上版本另有字节数比对流程）。

## 回归结果

| 项 | 结果 |
|---|---|
| 桌面四页（1440×1000） | **零回归**：文档尺寸、画布像素采样、控制台报错数与修前**完全一致** |
| 移动端（390×844，展开折叠区后） | 四页 **全部 0 溢出 / 0 被裁**（只剩表格类"容器内可横滑"，属可接受） |
| 对比度（渲染后实测） | `/` 175 处、`/orbit` 80 处、`/universe` 379 处、`/kids` 62 处 —— **全部 0 处不达标** |

**顺带修了一处环境漂移**：`_runall.sh` 与 `_verify_all.ps1` 里的 node 路径都指向
`22.22.2-3`，而本机 `versions/` 下**只有 `22.22.2-6`**（该目录 10-08 才建，10-07 那次全量跑完之后）。
两份入口**同改**，保持镜像（改一处必须改另一处）。

**另一处同轮改动（不是视觉问题，是判据可诊断性）**：同一轮全量跑里 D0 收集
`_probe_tools.js` 时报 `rc=1 且没有计划文件`。查下来是**间歇性**的 —— 该探针自
`f4367e1`(10-07) 起一行未改，独立跑能跑完（550.6 s / 86 次请求 / rc=2 / 204 条断言里
只有 6 条"命令没录到"）；它慢是因为**单条内核响应真的很大**（碎裂载荷
`/api/nbody` **33,962,510 B / 23.9 s**，进程峰值 RSS >1.2 GB）。
真正要补的是**证据保全**：D0 原来把 stderr 丢进 `/dev/null`，而探针抓到异常时是把
**栈写进它自己的 `_probe_<名>.txt`**（不是 stderr），那份 .txt 又会被 E 层同名探针覆盖 ——
等于**崩溃证据被抹掉**。现在每轮 stderr 留档、并把探针的 .txt 一并快照进
`_d0_<探针>.err`，失败信息里点名它。
