## P0-1 内核拒绝时，页面在撒谎

**复现**：`universe.html` → 场景切「自定义」→ 把 A 的 `e` 改成 `1.5` → 点「重新计算」。

**内核其实明确拒绝了**（这是对的）：

```
$ starpivot nbody --scenario custom --solar sun --body X,1,1.5,0,0,0,0,1e-6 --samples 5
starpivot: --body e must be in [0,1) (name X)      # 退出码 2
```

**但页面上什么都不会发生。** 实测：

```
内核请求体里的 e = [1.5,0.2]
内核拒绝后【同一瞬间】statline = starpivot: --body e must be in [0,1) (name A)   ← 错误确实写进去了
推进 1 帧之后        statline = 积分器 leapfrog（辛）· 能量漂移 7.34e-8 · ...    ← 被抹掉了
此时画面上仍显示的是：t = 0.050（旧数据还在）
端点/控制台异常 = 无
```

成因：`compute()` 的 `catch` 把错误写进 `#statline`，而 `render()` 每帧都重写那一行
（`tick` → `render`，约 60 次/秒）。所以错误提示在屏幕上活不到 16 ms，肉眼基本看不见；
同时画布继续显示**上一次成功**的轨道，玩家会认为 `e=1.5` 已经生效。

这条直接顶到本项目自己的定位上——「明确拒绝而不是返回一个看起来对的数」：
内核做到了，页面把拒绝信息擦掉了。

**已修**：新增 `#errbar` 告警条（`render()` 不碰它），明说
「这次重算失败了，画面没有跟着变。（画面上现在还是**上一次成功**的结果，t = X 年）」
+ 内核原话；下一次重算成功自动消失。

**判据**：`_probe_errbar.js` 12 项（含"推进 20 帧后告警条仍在"这条专门针对原缺陷）。
影响面覆盖所有失败路径：`e≥1`、`a≤0`、0 个天体、HTTP 5xx、180 s 超时。

## P0-2 `frames: []` 让页面冻死

**内核侧复现**（`--dt` 也没有校验）：

```
$ starpivot nbody --scenario solar --years 1 --dt 0 --samples 5
{ "status": "ok", ... "frames": [ ], ... }          # 退出码 0 —— 报告成功
$ starpivot nbody --scenario solar --years 1 --dt 1e-12 --samples 5
{ "status": "ok", ... "frames": [ ], ... }          # 同样
```

**页面侧后果**（jsdom 复现）：

```
TypeError: Cannot read properties of undefined (reading 't')
    at render (universe.html:681)   ← data.frames[fi]，fi 被钳到 0 但数组是空的
    at tick   (universe.html:831)
```

异常抛在 `tick` 里 → 末尾那句 `requestAnimationFrame(tick)` 永远执行不到 →
**链式动画断掉，整页冻死**：画面停在最后一帧，播放键、拖拽、缩放全都不再有反应。

**已修（页面侧）**：收到响应先做契约校验，0 帧就明确报错，而不是照单全收。

```
内核回了 status="ok" 但帧数为 0。页面需要至少 1 帧才能绘制，这属于内核契约问题。
```

**未修（内核侧）**：根因是 `--dt` 无校验。建议在 CLI 的 `--samples` 校验旁边加一句
`if (!(dt > 0)) die("--dt must be > 0")`——`status:"ok"` 配 0 帧本身就是自相矛盾的响应。

## P1-3 默认画面把圆画成多边形（最影响第一印象）

**这是我认为最该先修的一条。**

默认 50 年 / 400 帧 → 输出步长 0.125 年/帧。实测每颗行星相邻两帧之间的最大张角：

| 天体 | 单帧最大转角 | 相当于一圈只有 | |
|---|---|---|---|
| 水星 | **179.8°** | 2.0 个采样点 | 每帧跳到轨道对面 |
| 金星 | 74.8° | 4.8 个采样点 | |
| 地球 | 46.7° | 7.7 个采样点 | 八边形 |
| 火星 | 29.1° | 12.4 个采样点 | |

把帧数拉到页面允许的上限 2000，水星仍然是 58.3°（6.2 点/圈）。只有把年数压到 5 年
（5 年 / 2000 帧）才好看：水星 4.7°、地球 0.7°。

**这不是物理精度问题**：内核 `dt = 0.001 年`，50 年 = 50000 步，积分本身很准。
问题在**输出采样太稀**，而且页面**只按整数帧索引取位置、帧之间不做插值**
（`fi = frameIndex()`，位置就是 `frames[fi].p[b]`），于是"采样间隔"直接等于"肉眼看到的每次跳变"。

`400` 这个默认值看起来是个"好看的整数"，不是按最短轨道周期标定出来的。

**三个方案（需要你定调）**：

- (a) **内核回显 `suggested_samples`**（按最短轨道周期 × 每圈 N 点，例如 N=60），页面默认用它。
  最符合本项目"内核才算数"的分工，且顺带解决了自定义场景里玩家加了水星轨道后同样混叠的问题。
- (b) **页面在帧之间做线性插值**（纯渲染，不碰物理）。能彻底消除跳变，但会触碰
  "本页零计算"这条纪律——插值算不算"计算"，得你定。注意 `_check_bio_page.js` 里
  有一条"剥掉字符串后页面不该出现物理常量"的判据，插值不会违反它。
- (c) 退一步：把**"每圈采样点数"作为画质读数显示给玩家**，让他自己调年数/帧数。
  最保守，但也最像把问题推给用户。

我的倾向是 (a) 打底 + (c) 兜底。

## P1-4 六个控件改了不重算，而且一句话都不说

判据信号用的是最不含糊的那个：**改完这个控件之后，页面有没有真的再发一次内核请求**。

| 控件 | 改完会自己重算吗 |
|---|---|
| 场景 / 太阳系档位 | ✅ 会 |
| 演化开关 / 阶梯年数 / albedo / 温室增温 | ✅ 会 |
| **碰撞模式** | ❌ 不会，且无提示 |
| **半径放大 ×** | ❌ 不会，且无提示 |
| **碎块数 / 色散速度 / 碎裂阈值** | ❌ 不会，且无提示 |
| **恒星参与碰撞** | ❌ 不会，且无提示 |
| 积分年数 / 输出帧数 | ❌ 不会（这个可以理解，重积分要 0.4–1 s） |

按场景归类的话，同一张卡片里的两组旋钮行为是相反的：演化组自动重算，碰撞组不自动。
玩家把「半径放大 ×」从 450 调到 3000，期待更容易看到碰撞，结果什么都没发生——
他甚至没有任何线索知道要再按一次「重新计算」。

**建议**：不要简单地改成全部自动重算（滑杆拖动会把内核打爆，这正是当初演化组
只在 `change` 而不是 `input` 上重算的原因）。更好的做法是**脏标记**：
参数一改，就把「重新计算」按钮变成高亮态并在旁边写明「参数已改，点这里重算」，
重算完清除。这样既不打爆内核，也不会有"改了没反应"的黑箱。

## P1-5 内核 `--years` 完全没有校验

`--samples` 有 `[2,4000]` 的校验且报错清晰；`--years` 和 `--dt` 一条都没有。真跑结果：

| 输入 | 实际行为 |
|---|---|
| `--years abc` | `libc++abi: terminating due to uncaught exception of type std::invalid_argument: stod: no conversion`，**未捕获异常、进程 abort**（退出码 3221226505 / 0xC0000409） |
| `--years 1000000` | 不拒绝，直接跑（25 s 被我掐断还没结束）。按 50 年/500 年两点斜率外推，量级是**数百秒**；网关 180 s 超时 → 玩家白等 3 分钟看到 504 |
| `--years -5` | 静默变成 50（回显 `"years": 50`） |
| `--years 0` | 合法返回，`"years": 0`，frames 只有一条 t=0 |
| `--samples 4001 / 1` | `starpivot: --samples must be in [2, 4000]`（退出码 2）✅ |

页面侧：「积分年数」输入框没有 `min`/`max`，输 `0` 或留空 → `+value \|\| null` → **不发送**
→ 内核静默用默认 50 年（实测：`发给内核 years = null`）。也就是玩家输了个 0，跑了 50 年，没人告诉他。

**建议**：
1. CLI 里 `--years` 加范围校验、`--dt` 加 `> 0` 校验，且用 `die()` 报错而不是让 `stod` 的异常逃出去；
2. 页面输入框补 `min`/`max`，并对"被静默改写的值"给出提示；
3. 大年数在页面上给出耗时预估（内核已经把 `dt_years` 回显出来了，能算）。

## P1-7 `index.html` 的主视图是打包样本，页面没说

实测加载后页面发出的内核请求只有 **1 次**：`/api/health`。
轨迹地图、高度剖面、关键量、模型表**全部来自 `demo.js` 里烘焙的 `STARPIVOT_DEMO`**（246 KB）。
切场景能换三份数据，但年数/帧数没有任何入口——玩家改不了。

页面副标题写的是「轨迹与碰撞预警均为本机 starpivot CLI 的真实输出」。
**这句话本身不假**（确实是 CLI 输出），但它是**打包时算好的**，不是现在这台机器现算的。
玩家很容易以为自己在跑本地内核，尤其是同一站点的 `universe.html` 每次都真的在调内核、
还反复强调"本页零计算"。同一套页面里两种口径，对照之下 `index.html` 这句就显得含糊。

（对照：只有「运行 conj」和「从真实编目找近距对」两个按钮是真·现场调用，那两个是对的。）

**建议**：在主视图旁边加一句「这三份是随页面打包的预计算样本，改参数重算请用命令行
`starpivot verify-tle ...`」，或者干脆改成现场调用（`/api/verify-tle` 已经存在）。

## P2 玩法缺失：作为"模拟器"真正缺的东西

先说定位判断：**它是科学模拟沙盒/技术演示器，不是游戏。**
作为游戏评审，它缺"目标 → 反馈 → 进展"三段闭环；但作为模拟器，核心可玩性是成立的
——自定义宇宙 + 碰撞碎裂重聚 + 位置驱动的演化阶梯，这三个是真正能产生"涌现"的地方。
问题在于它们被两件事挡在门外：默认参数不好看（P1-3）、改了参数没反馈（P1-4）。

| # | 缺什么 | 为什么值得做 |
|---|---|---|
| 8 | **时间导航**：只能播放/暂停 + 拖 scrub | 演化面板已经告诉你"第 4 阶在 23.5 年达到"，却点不过去。缺：单步、上一帧/下一帧、**跳到事件时刻**（碰撞/碎裂/重聚那一帧）、**跳到某颗星达到某阶的时刻**。数据全都有，纯前端就能做——这是性价比最高的一条 |
| 9 | **新手指引** | 首屏是俯视图 + 一排滑杆，页面没有任何"你可以试试…"。三体场景更是零自由度（初值固定，只能改年数）。README 里有玩法，页面里没有 |
| 10 | **自定义是唯一真有自由度的玩法，入口太硬** | 9 个裸数字框。没有预设模板（类地行星 / 热木星 / 双星 / 彗星），没有滑杆，不能在画面上拖出一个新天体。默认那组"真会撞上"的 A/B 是全项目最好的演示，却埋在第一层 |
| 11 | **分享 / 导出** | 会话持久化只保一个"宇宙"，不能命名、不能多存档；不能导出 PNG / JSON。分享只能靠发布链接 |
| 12 | **碰撞演示默认看不到** | 默认场景是太阳系；要看到撞击→碎裂→重聚得自己切到自定义。页面确实写了"默认 A/B 是一组真会撞上的初值"，但这句话在切过去之后才出现 |

## 这次审查里我自己写错的判据（一并记下）

审查工具本身也会骗人，四条都栽过：

1. 把 `/api/health` 也数成"内核调用"，于是"首屏调了 2 次内核"是个假结论；
2. 在改旋钮**之前**就点了暂停，没意识到每次改旋钮都会重算、而重算后按既有行为会自动继续播放 →
   之后所有控件的指纹一直在变，全被判成"立即生效"；
3. `fetchLog` 记的是"请求已发出"，我拿它当"响应已收到"用，于是"错误提示还在"是读到了上一次的残留；
4. 用"有没有那个告警色"判断告警是否还在——`render()` 在未回显 `ic_helio` 时也会写一段同色文字，
   判据于是自我欺骗。

最后一条也是为什么 P0-1 那条结论是基于**两段文字的直接对比**给出的，而不是某种启发式。
