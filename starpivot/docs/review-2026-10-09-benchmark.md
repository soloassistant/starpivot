# 同类产品对标（第三轮）：2026-10-09

日期：2026-10-09
对象：`starpivot` —— C++17 物理内核（11 个子命令 / 16 个 `.cpp` / 19 个 `.hpp`）+ 四页前端
（`home` / `index` 轨道递推 / `universe` N 体 / `kids`）
方法：先查同类产品的公开资料（**逐条标注来源强度**），再按"能不能对上我们的功能面"拆解，
最后把差距落到改动建议上。

**本轮与 9-25 那轮的关系**：9-25 那轮列了 25 个产品，当时的结论是"我们内核更可验证，
但页面上一个字节都没露"。那之后我们做了很多（Lagrange、genesis 随机宇宙、双模式、
点画面放行星、信息卡、keep-alive 修复、判据扩到 48 条）。**这一轮的重点是把市面重新扫一遍，
看我们补上的东西别人有没有、别人补上的东西我们有没有。** 结论是：**我们在两个新方向上
（真实数据 + 可交互 N 体 + 拉格朗日三合一、以及"可验证"）站住了，但在一个方向上
（真数据场景库的规模）被拉开了整整一个数量级。**

---

## 一句话结论

**九月份那批竞品的吸引力没有变（零距离反馈、目标感、真数据）——
但这一轮扫出来的"浏览器免费 + 真物理"这一环，比 9-25 那轮以为的拥挤得多，
而且它们开始做两件我们没做的事：把模型做不到的地方明说出来，以及把真数据做成可检索的库。**

前一件我们其实做得更彻底，只是**没翻译成玩家看得懂的一句话**；
后一件**是我们唯一被拉开一个量级的地方**，而且补起来最便宜。

## 三、我们真正强的地方（把 9-25 之后的新能力计入）

1. **同一套内核里同时有 11 个子命令**：
   `propagate / elements / j2 / verify-tle / conj / groundtrack / nbody / lagrange / genesis /
   catalog / about` —— 恒星星历 → 真实 TLE（SGP4）→ 碰撞预警 → N 体辛积分 → 拉格朗日点 →
   随机宇宙生成 → 生物/演化阶梯，**四页共用**。
   **对撞结果**：竞品里只有 Gravity Simulator 在"真实数据 + 可交互 N 体 + 拉格朗日"三项都齐，
   但它**物理不公开可复算**。我们这一条仍然站得住。
2. **分层诚实 + 常量一律内核回显 + 缺失不补零**。
   `real_exoplanets.json` 里自带 `warning`：「含有观测缺项；缺项一律保持缺失，不补零、
   不用同类天体顶替」。取数用的是 **pscomppars（每行星一行最佳综合值）而不是 ps**
   —— 因为 ps 表同一颗行星会因不同文献出现多行、直接取会拿到互相矛盾的参数。
   **这条判断在竞品里我没见第二家做过。**
3. **五层判据 48 条 + A0 清单对账**（`_verify_all.ps1` / `_runall.sh` 两份同改，
   `_cmp_lists.py` 验集合/顺序/标签三者一致）。**同类里没有第二家把"可验证"做到能查。**
4. **真数据带完整溯源**：`data/PROVENANCE.md`（28 KB）+ 两份专项溯源
   （`PROVENANCE-exo_mass_prov.md`、`PROVENANCE-star_teff_bc.md`），
   **连查询语句和取数日期都写在文件里**（NASA Exoplanet Archive `pscomppars`，2026-09-26；
   ESA Hipparcos `I/239/hip_main`，Vmag<2.5，60 颗）。
5. **覆盖"不是给天文爱好者的那一半"**：`kids` 页（点一下放一颗行星的玩法）+ 三层判据，
   对标的正是 Solar System Scope「4 岁也能玩」那条。

## 七、取证与不确定项（诚实标注）

**本轮直接抓取的资料页**（来源强度=强）：
Gravity Simulator 官方 About 页与场景列表；Luna Space Simulator 官方站（+ 3 个第三方目录佐证）；
Super Planet Crash / Orbits / GravityKit 作者项目页 + McDonald Observatory 新闻稿 + Space.com；
Orbitarium 的 Chrome 应用商店页；Gravity Sandbox（siddharthroy12 / AgastyaTeja1 / ant3mc）
的 GitHub README；Solaray-3D 的 GitHub README；NASA Eyes 官方站与 NASA 官方通讯。

**派生统计数据**（来源强度=中，方向可用、数字标注为派生）：
Universe Sandbox 的 SteamDB / SteamPeaks / isitdoneyet（96.5%、32.4K 评测、$20.09、
Update 36.x 时间线、游玩人数）；SpaceEngine 的 Steam 派生站。

**明确的不确定项（不要拿去做决定）：**

1. **`starpivot` 没有 Barnes-Hut / 大 N 加速**——已核实：全库 grep `barnes|hut|octree|quadtree|tree-approx`
   零命中（`src/spin.cpp` 与 `hermite.hpp` 里的 "Hut" 是**作者名**，不是树近似），
   `src/gravity.cpp` 是 O(N²) 直接两两求和。**大 N 场景我们比 Luna / Gravity Simulator 慢。**
2. **Luna 的全部细节来自其官方概览页，未实际打开模拟器验证**；
   "全 N 体""辛积分""Barnes-Hut 切换"均为其自述。
3. **SpaceEngine 价格三源互斥**（$24.99 与 $29.99 都出现过），只标注为"约 $25–30 区间"。
4. **我们的四页在手机上从未验证**——`index.html` / `universe.html` 里有响应式声明，
   但**做过的是"结构性声明"的静态核对，不是真机目视**。
5. **`_verify_all.ps1` 无"跑过"的证据**：本机 PowerShell 不可用（工具零输出，
   从 bash 调被安全策略拦），48 条只在 bash 镜像 `_runall.sh` 上跑过全绿。
   **"正式入口本身绿过"这句话目前没有证据支撑。**
6. 稳定性的命名**跨端点不统一**（同一概念两处命名不同），这是已知的、未修项。
7. 本轮**未做任何浏览器目视验收**——所以本文档里**没有一条关于"好不好看"的结论**，
   只有"功能面上有没有"。

> **方法上的自我提醒**：本轮的"对撞表"是**功能面清单**，不是"谁更好"的判决。
> 一条"我们前"只说明**这一项我们做了、对方资料里没写**，
> 不说明"对方真的没有"（对方可能做了但没写在资料页上）。
> 这是所有"扫公开资料"类对标共同的边界，须与结论一起读。
